# kb v2.4.5 发布说明（2026-11-04）

Excel 表格兼容性与确定性问答优化。重点解决两类真实问题：**导出的 xlsx 打不开/被判定为空**，以及**多 sheet 同名实体把整行原文倒出来**。

## 修复

### 1. 兼容不带 `<dimension>` 的 xlsx

财务系统、BI、部分 WPS 另存出的 xlsx 不写 `<dimension>`。`openpyxl` 的只读模式依赖该字段，会读到 0 行，旧版报“表格为空或没有数据行”。现在解析前重置工作表维度再扫描，18 个 sheet 的企业经营总表可正常入库（800 条，约 24s）。

### 2. 多 sheet 同名实体只返回目标列有值的表

问「上海宏图科技有限公司的联系电话」时，销售订单、应收账款里也有同一个公司名，旧版会把整行都答出来。现在按“问题点名的列”给行打分，只保留覆盖度最高的行：

```text
客户档案 上海宏图科技有限公司：联系电话=18784801454
```

### 3. 公式单元格不再作为答案

`openpyxl` 对没有缓存结果的公式只能读到公式原文。现在答案提示“为公式，文件未保存计算结果”，Web UI 的来源卡片也不再显示 `＝SUM(...)`。

### 4. 其他解析修复

- 标题行识别：表头上方的「附件」「2026年招聘岗位表」不会再被当表头；
- 合并单元格续行补全：企业名称/联系人/联系电话/工作地点为空时沿用上一行；
- `.xls` 支持：可选依赖 `xlrd`，已加入 `[ingest]` / `[full]`；
- 日期单元格输出去掉 `00:00:00`。

## 问答与界面

- 列名同义词：`薪资待遇/工资/薪酬` → 「薪酬待遇」，`电话/手机` → 「联系电话」；
- 列表问题：`8月第2期有哪些企业` 去重列出并给数量；
- 按值反查：`18783977706 是谁的电话`、`5000-15000 是哪个岗位` 标签回到公司名；
- 限定条件：`薪酬5000以上`、`学历要求本科`、`工作地点在X`、`列名是/为X`；
- `/api/v1/search` 支持 `table=true`，仅检索（不调用 LLM）也能返回结构化表格答案；
- Web UI 来源从 `列名=值 | ...` 改为「字段 / 值」两列，公式列自动隐藏；
- `/api/v1/healthz` 返回 `version`，页面「服务在线」悬停可确认实际运行版本；
- 上传超限提示改为 MB 级别，并说明可用 `KB_MAX_UPLOAD_BYTES` 调整。

## 验证

- 全量：**560 passed / 1 skipped / 94.55s**（Windows，Python 3.10，ChromaDB 1.5.9）。
- 真实文件：`企业经营数据总表_2026.xlsx`（18 sheet / 800 行）
  - API 上传：**200**，`chunks=800`，24.57s；
  - 5 个典型问题的答案均只保留目标行，约 57–70ms。
- 新增用例：无 `<dimension>` 的 xlsx、同名实体跨 sheet、公式值、日期格式、来源渲染、healthz 版本。

## 升级

```bash
pip install -U "kb-memory[ingest]"
```

`.xls` 需要 `xlrd`，`[ingest]` / `[full]` extra 已包含；老用户升级后建议重启 `python -m kb serve`，新代码才会生效。

## 边界

- 整表聚合/跨表统计仍不是确定性规则的强项；没有缓存结果的公式无法计算；
- 单文件上传上限默认 100MB（`KB_MAX_UPLOAD_BYTES`，0=不限）；表格的实际可处理行数还受内存与入库耗时约束。
