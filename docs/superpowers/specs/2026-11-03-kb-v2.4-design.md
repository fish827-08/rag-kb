# kb v2.4 设计：表格问答、知识图谱可视化、RAG 与记忆分离

> 状态：✅ 有效（当前版本设计增量）。基线仍为 `2026-08-23-kb-memory-service-design.md` 与 `2026-10-20-kb-v2.1-design.md`；与本文冲突处以本文为准。

## 1. 目标（用户诉求）

| 编号 | 诉求 | 验收口径 |
|---|---|---|
| R1 | 导入 CSV / Excel 表格，并可按数据精准问答 | 上传成绩表后问「小明的语文成绩」，无需 LLM 也能答出「95」 |
| R2 | 知识图谱可视化 | Web UI 可看到记忆节点与关联边，点击节点查看内容 |
| R3 | RAG 导入内容与模型记忆分离 | 文档/网页/表格记录不参与遗忘与衰减；界面/接口可按来源区分 |
| R4 | 页面细节 | `/favicon.ico` 不再 404；LLM 配置不再预填/强绑定 DeepSeek 过时值；保存有成功/失败提示；支持整文件夹批量导入 |

## 2. R1 表格导入与精准问答

### 2.1 解析（新增 `kb/tables.py`）

- 支持扩展名：`.csv`、`.xlsx`、`.xlsm`、`.xls`。
- CSV：标准库 `csv`，编码先 `utf-8-sig`，失败回退 `gbk`；首行作表头。
- XLSX/XLSM：可选依赖 `openpyxl`（加入 `[ingest]` extra）；逐 sheet 读值，跳过全空行。
- XLS：可选依赖 `xlrd`（加入 `[ingest]` extra）；逐 sheet 取单元格，日期转 `YYYY-MM-DD`。
- 表头识别（v2.4.5）：扫描前 10 行，取“非空单元格最多且含表头关键词”的一行，避免把上方的
  标题行（如「附件」「2026年招聘岗位表」）当成表头；空列补「列N」，重名追加 `_2`。
- 合并单元格（v2.4.5）：企业名称/主管部门/联系人/联系电话/工作地点为空时沿用上一行，
  让“一个公司多个岗位”的续行也能被公司名检索到。
- 输出统一结构：`[{"sheet": 名称, "headers": [...], "rows": [[...]]}]`。

### 2.2 入库形态

- 表格仍写入 `doc_chunk`（不进 memory 桶，天然不参与遗忘）。
- `tags` 追加 `table`；`source` 为「文件名」，多 sheet 时 `source = 文件名#sheet`。
- 每行一条记录，内容格式：`列名=值 | 列名=值`（保留表头语义，便于 BM25/向量命中）。
- 行数超过 `TABLE_MAX_ROW_RECORDS`（默认 500）时，按 `chunk_size` 聚合成多行文本块，仍保持「每行一条 `列名=值 | ...`」，保证确定性查询可逐行解析。
- 首个 chunk 之外不额外写表头记录，表头信息随每行重复，检索与问答都不丢列语义。

### 2.3 确定性表格问答（`KBService._table_answer`）

`ask` 在 LLM 可用性检查之前先尝试表格查询：

1. 收集当前作用域（项目库 + 全局库）中 `tags` 含 `table` 的记录，逐行解析为 `{列名: 值}`；
2. 命中规则：问题中出现某行任一单元格值（长度 ≥ 2，且纯数字需 ≥4 位，避免分数 50 误命中「1500」）→ 该行为候选；问题中出现列名 → 作为列过滤；
3. 多 sheet 消歧：行首 `[表名]` 前缀解析到 `__sheet`；问题中出现表名（如「五班」）时只保留该 sheet 的行，多个表名互为子串时取最长匹配（「十五班」优先于「五班」）；
4. 唯一/多行命中时，按「[表名] 行标识 + 列名=值」组织答案；若问题含「总分/合计/求和」「平均」，对数值列做聚合；聚合排除学号/序号/已有总分列；
5. 命中不足（无行或无法确定）时返回 `None`，走原 RAG 流程（不改变既有行为）。

v2.4.5 增强（仍为确定性规则，不调用 LLM）：

- **列名同义词**：`薪资待遇/工资/薪酬` 归到「薪酬待遇」，「电话/手机」归到「联系电话」等；
  表头先去掉括号单位再匹配，`薪酬待遇（元/月）` 与 `薪资福利待遇（…）` 都能命中；
- **同名多行**：同公司多个岗位全部保留；共享字段只输出一次，岗位合并为「A / B / C」；
- **按值反查**：`18783977706 是谁的电话`、`5000-15000 是哪个岗位` 先命中单元格值，
  标签回到公司名，再输出命中的字段；
- **列表问题**：`有哪些企业 / 哪些岗位` 去重后按序号列出，并给出数量与表名；
  列表目标取离「有哪些」最近的词，避免表名里的「岗位清单」抢走「有哪些企业」；
- **限定条件**：`薪酬5000以上`（按区间上限筛选）、`学历要求本科`、`工作地点在X`、
  `列名是/为X`；条件里的数字不再被误当作单元格定位键；
- **中文表名**：`八月份第2期` 归一为 `8月2期`，可匹配 sheet「8月第2期」。

返回结构复用 `/ask` 契约：`{"answer": ..., "sources": [...], "llm": "table", "table": true}`。
`/api/v1/search` 增加可选 `table=true`：先尝试确定性表格问答，命中则返回
`{"table": true, "answer": ..., "sources": [...]}`，让“仅检索（不调用 LLM）”也能读懂表格。
未命中时行为与 v2.3 完全一致。

## 3. R2 知识图谱

### 3.1 接口

`GET /api/v1/graph?project=<name>&limit=<1..500>`（默认 200）：

```json
{
  "nodes": [{"id": "...", "label": "内容摘要", "type": "memory",
             "project": "", "tags": ["..."], "degree": 2}],
  "edges": [{"from": "...", "to": "...", "relation": "related"}],
  "truncated": false
}
```

- 节点只含 `type=memory` 的记录（RAG 文档块不进图谱，落实 R3 的分离）；
- 边来自各作用域 `links.db`；只保留两端都在节点集合内的边；
- 项目参数存在时合并项目库 + 全局库节点，默认全局库；
- `limit` 上限 500，超出按关联度/更新时间截断并置 `truncated=true`。
- `LinkStore` 增加只读方法 `all_edges()`。

### 3.2 前端

- 新增「记忆图谱」卡片：内联 SVG 环形布局（度数高的节点在内环），边按关系着色，节点可点击，右侧显示节点内容与标签；
- 图谱与文档列表分离展示：文档列表保持 RAG 内容，图谱仅展示记忆节点。

## 4. R3 RAG 与记忆分离、不遗忘

- 检索排序中的衰减（`decay_enabled`）与新鲜度（`freshness_enabled`）只作用于 `type == memory`；`doc_chunk` / `web_chunk` 的分数不乘任何衰减因子。
- `kb forget` 默认 memory-only 的行为不变，并补测试锁死（`include_documents` 才纳入文档）。
- 文档列表按 `source` 聚合，界面文案明确「文档/网页/表格属于 RAG 知识库，不参与遗忘」。
- 文档写明：RAG 内容只在显式删除时移除。

## 5. R4 页面修复

- 根导航页与 `/ui` 均声明内联 favicon；新增 `GET /favicon.ico` 返回 SVG 图标（200），消除浏览器直接请求导致的 404。
- `kb/config.py` 云端 LLM 默认值改为空串（不再预填 DeepSeek 地址/模型）；旧 `deepseek_*` 兼容键仍在读取时生效，但内置默认清空。Web UI 用 placeholder 提示「任意 OpenAI 兼容端点」。
- 保存 LLM 配置已有成功/失败 toast，保留并纳入回归测试。
- 文件夹批量导入（`webkitdirectory`）保留；前端过滤白名单扩展名。

## 6. 兼容性与依赖

- 新增可选依赖：`openpyxl`（仅 `[ingest]` / `[full]` extra，用于 XLSX 精确逐行解析）；不装时 CSV 与其余格式不受影响，XLSX 返回安装指引。
- 新增模块 `kb/tables.py`：设计内新增（本文件即授权依据），职责单一（表格解析与行查询），不引入常驻服务。
- REST 契约向后兼容：仅新增 `/api/v1/graph`，`/ask` 仅新增可选 `table` 字段与 `llm="table"`。

## 7. 验收（自动化）

- `tests/test_n38_graph.py`：/graph 节点/边/项目合并/limit、文档块不入选。

## 8. v2.4.6 增量（2026-11-07）

- **数据目录单例**：新增 `kb/singleton.py`，在 `KB_DATA_DIR/kb.lock` 上加 OS 文件锁；
  `serve` 与 stdio `mcp` 抢锁，短命写命令只警告不阻塞。锁按数据目录而非端口，
  换端口不能绕过；锁文件与信息文件分离，规避 Windows 字节锁阻断读取。
- **`kb serve --port`**：监听端口可在命令行覆盖，默认仍取 `KB_API_PORT`。
- **表格行跳过嵌入**：表格记录使用常量单位向量入库，不调用嵌入模型；
  写入按 2000 条分批（Chroma 单次上限约 5461），2 万行可正常入库。
- **表格行缓存**：`_table_rows()` 按作用域缓存解析后的行与来源，写入时由
  `_bump_table_epoch()` 失效；首次查询建缓存，之后不再重扫 Chroma。
- **检索结果按文件聚合**：`/api/v1/search` 新增 `group_by_file`，额外返回 `files`。
- **MCP 表格参数**：`search_memory(table=true)` 先走确定性问答，未命中回退检索。
- **嵌入模型可选**：`GET/POST /api/v1/embed[/config]`；库非空时锁定，空模型名拒绝。
- **多实体匹配**：先按命中值个数收窄，再按“最长命中是否被真包含”裁剪。
- **CLI**：新增 `kb table query`；删除与 `python -m kb serve` 重复的
  `scripts/windows/start_kb_console.bat`。
- **验收**：新增 `tests/test_n43_v246_features.py`（16 例），全量 578 passed / 1 skipped。
