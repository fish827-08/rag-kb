## 1. 批量循环时序

```
worker 唤醒
  1. 查卡：search "TASK claimed {名字}"（中断恢复，优先续做）→ 有则从该卡续做（计入轮次）
  2. 进入批量循环（BATCH_MAX_ROUNDS=5 轮 / BATCH_TIME_WINDOW=30 分钟，先到为准）：
     每轮：
       a. 查 pending：search "TASK pending {名字}"（只看分配给自己的卡）
       b. 无 pending → 收尾待命（不空转）
       c. 有 pending → 认领：首行 pending→claimed（原子，非 pending 报错不误改）
       d. 执行：按卡内 目标/输入/约束/验收，只做目标范围内
       e. 回写：首行改 done/failed + "结果：" ≤1000 字符（分支卡注明提交哈希）
       f. 交流窗即报：写 comm:done（谁/哪张卡/产出物/哈希，≤300 字符）——单卡完成即报
       g. 检查保险丝：轮次 ≥5 或时间窗到 → 收尾待命；否则进入下一轮
  3. 收尾：执行摘要（≤200 字）后结束回合
```

- **中断恢复**：唤醒先续做 claimed 卡；该卡计入本轮轮次（防"无限续做"绕过保险丝）
- **无卡即停**：任一轮查不到 pending 立即收尾，不空转、不轮询

## 2. 轮次与时间窗双保险丝参数表

| 参数 | 默认 | 语义 |
|---|---|---|
| `BATCH_MAX_ROUNDS` | **5** | 单次唤醒累计最多处理 5 张卡（含续做的 claimed 卡） |
| `BATCH_TIME_WINDOW` | **30 分钟** | 从批量循环开始（第 1 张卡认领起）计时，到点即收尾 |
| 触发规则 | 先到为准 | 轮次达上限 或 时间窗到，任一触发即收尾待命 |

- 两参数为**协议级常量**（写进 worker-prompt.md 与 skill），不新增代码配置项（批量是 AI 行为约束，非服务配置）
- 参数值来源：ROADMAP B1.4"单轮 5 轮上限" + v2-iteration §4 既有"5 张/30 分钟"；后续 B3 成本管控可再调（滚动配额），本期固定常量

### 3.2 新增"批量循环"节（置于"查卡"节之后）

```
## 批量循环（取代单卡单轮）

- 唤醒后先查 claimed（中断恢复，优先续做，续做计入轮次），再进入批量循环：
  领卡 → 执行 → 回写 → 写 comm:done → 查下一张，直到无卡或触发保险丝
- 每完成一张卡即写一条 comm:done（谁/哪张卡/产出物/分支哈希，≤300 字符）
- 单卡原子性不变：认领（pending→claimed）与回写（→done/failed）按原有方式操作
```

### 3.3 新增"轮次保险丝"节（置于"纪律"节）

```
## 轮次保险丝（铁律）

- 轮次上限：单次唤醒累计最多处理 5 张卡（BATCH_MAX_ROUNDS）
- 时间窗：从批量循环开始 30 分钟内收尾（BATCH_TIME_WINDOW）
- 先到为准：轮次达上限或时间窗到，任一触发即收尾待命；未处理完的卡留给下次唤醒
- 中断恢复：claimed 卡续做计入轮次，防止绕过保险丝
```

## 4. board.py 无改动论证（领卡本身原子）

- **认领原子**：`cmd_claim`（TASK-0004 已实现）对非 pending 卡报错不误改，pending→claimed 是一次 PATCH，天然原子；批量只是同一原子操作在单次唤醒内多次调用，**无需新增/修改 board.py**
- **分配语义不变**：卡首行 assignee 由协调者建卡时指定；worker 只查 `TASK pending {自己的名字}`，不会抢他人卡
- **并发安全**：多 worker 并行时各自认领自己的卡；同一卡被并发 claim 时先到者成功、后到者报错并继续下一张（不阻塞）
- **超时语义不变**：claimed 超 30 分钟无 done 由协调者打回 pending（协议 §4.5），批量不改变

## 5. 边界情况

| 场景 | 行为 |
|---|---|
| 中途无卡 | 任一轮查 pending 为空 → 立即收尾待命，不空转 |
| 达轮次上限 | 满 5 轮 → 收尾待命（即使还有 pending，留给下次唤醒） |
| 时间窗到 | 30 分钟到（不足 5 轮）→ 收尾待命 |
| 单卡执行失败 | 回写 failed（计入轮次），继续下一张；失败是结果不是异常 |
| 服务不可用 | 查卡/回写连接失败 → 停止批量、回写 failed 说明、待命（不自行拉起服务） |
| 中断恢复 | 唤醒先续做 claimed 卡（计入轮次），续做后再继续批量 |
| 多 worker 并行 | 各认领自己的卡，claim 原子防重复；并发失败者继续下一张 |
| 交流窗 | 每卡完成即报 comm:done；与卡内结果重复的信息只进卡不进窗（协议 §7 不变） |
